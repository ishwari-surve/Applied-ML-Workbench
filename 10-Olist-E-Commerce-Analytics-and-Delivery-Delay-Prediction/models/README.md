# 🤖 Models — Olist E-Commerce Delivery Delay Prediction

## 📌 Overview

The `models` directory stores the trained machine learning model used in the **Olist E-Commerce Analytics and Delivery Delay Prediction** project.

The saved model is generated by the Python machine learning pipeline and can be loaded for delivery-delay prediction and evaluation without retraining the model each time.

## 📂 Directory Structure

```text
models/
├── README.md
└── Best_delivery_delay_model.joblib
```

## 🧠 Model File

### `Best_delivery_delay_model.joblib`

**Format:** Joblib serialized Python object (`.joblib`)

**Purpose:** Stores the trained machine learning pipeline selected during model comparison.

The saved pipeline may contain:
- Data preprocessing steps.
- Missing-value imputation.
- Numerical feature scaling.
- Categorical feature encoding.
- The fitted classification model.

The exact model algorithm can be confirmed from the model-selection results produced during project execution.

## 🎯 Prediction Objective

The model performs binary classification to identify whether an eligible delivered order arrived later than its estimated delivery date.

| Target | Meaning |
|---|---|
| `0` | Delivered on time or earlier |
| `1` | Delivered after the estimated delivery date |

## ⚙️ Model Development Workflow

1. Prepare the analytical dataset and engineer predictive features.
2. Create the `is_late` target variable.
3. Remove target leakage from model inputs.
4. Split data chronologically into training and testing sets.
5. Build and compare classification pipelines using time-series cross-validation.
6. Select the best-performing model based on Average Precision.
7. Train the selected model using the training dataset.
8. Save the trained pipeline using Joblib.
9. Load the saved pipeline for evaluation and prediction.

## 📊 Model Evaluation

The project evaluates the selected model using:

- **Average Precision** — assesses the ranking of late deliveries.
- **Precision** — measures the accuracy of late-delivery alerts.
- **Recall** — measures how many actual late deliveries are detected.
- **F1-score** — balances precision and recall.
- **Confusion Matrix** — summarizes correct and incorrect classifications.
- **Precision–Recall Curve** — illustrates the trade-off between precision and recall.

Actual evaluation scores are generated during execution and are not specified in this README.

## 🔄 Loading the Saved Model

The model can be loaded using Joblib:

```python
import joblib

model_path = "models/Best_delivery_delay_model.joblib"

loaded_model = joblib.load(model_path)
```

For prediction, provide input data containing the same feature columns used during model training:

```python
predictions = loaded_model.predict(X_new)
probabilities = loaded_model.predict_proba(X_new)[:, 1]
```

`X_new` must follow the expected feature schema. The preprocessing steps stored in the pipeline handle the transformations learned during training.

## ⚠️ Important Considerations

- Load only trusted `.joblib` files.
- Use the same feature schema and compatible library versions as those used during training.
- Do not include information that would reveal the actual delivery outcome when predicting before delivery.
- Evaluate the model on unseen data before considering operational deployment.
- Treat predicted probabilities as model estimates, not guaranteed delivery outcomes.
